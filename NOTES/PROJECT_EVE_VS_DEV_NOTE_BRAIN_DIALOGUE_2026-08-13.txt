1. BRAIN / THOUGHT / DIALOGUE ARCHITECTURE
============================================================

Locked direction:

WORLD / PLAYER
    ↓
NPC BRAIN
    ↓
THOUGHT ENGINE
    ├─ Private Thought
    ├─ Fast Trait TAGS
    └─ Involuntary Body LEAKS
            ↓
       TraitEngine
            ↓
   Communication Mode
      /          \
     /            \
TEXT DIALOGUE   IN-PERSON DIALOGUE
     ↓              ↓
typed words     conscious body presentation
                + spoken dialogue

Core rule:
The simulation creates the character state.
The dialogue model gives that state a voice.

The LLM should not become the source of truth for:
- personality
- history
- relationships
- traits
- memory
- needs
- world facts

============================================================
2. THOUGHT ENGINE
============================================================

ThoughtEngine remains shared for all communication modes.

New structured output:

THOUGHT: <private internal thought>
LEAKS: <0-3 involuntary physical cues OR none>
TAGS: <Fast trait changes OR none>

Example:

THOUGHT: Don't let him see how much that hurt.
LEAKS: eye_break_short; jaw_tight
TAGS: trait.hurt+3@7; trait.guard+2@6

Responsibilities:
- interpret current situation
- react using personality/history/relationship/current state
- produce small Fast trait changes
- produce involuntary physical leakage
- never directly modify Mid traits
- never directly modify Slow traits

Text mode:
LEAKS must be none because the player cannot see the NPC physically.

In-person:
LEAKS can be visible to the player.

============================================================
5. IN-PERSON DIALOGUE
============================================================

New engine:
DialogueEngineInPerson

ThoughtEngine decides:
LEAKS = involuntary body behavior

DialogueEngineInPerson decides:
PRESENTATION = conscious social/body behavior
SAY = spoken words

Output contract:

PRESENTATION: <0-2 deliberate actions OR none>
SAY: <spoken dialogue>

Example:

Thought:
LEAKS: eye_break_short; jaw_tight

Dialogue:
PRESENTATION: folds her arms and steadies her voice
SAY: I'm fine.

Player-visible result:

*Her eyes flick away for a second and her jaw tightens.
She folds her arms and steadies herself.*
"I'm fine."

Important:
Unconscious body language and conscious body language can contradict each other.

7. HISTORY / MEMORY PROMPT INTEGRATION
============================================================

Locked architecture:

HistoryEventRow
= objective-ish world event truth

HistoryRecord
= personal life-history meaning

MemoryRecord
= retrievable personal memory

Gossip
= transmitted belief that may be distorted

Do NOT use:
HistoryRecord.ToString()

Use actual HistoryRecord fields:
- Summary
- Age
- Category
- Importance

Memory retrieval:
MemoryDatabase.GetMemories(owner.Id, ...)

NpcId remains authoritative.

Both Thought and Dialogue should receive:
- selected important history
- selected relevant/high memories
- recent conversation

Do not dump the entire memory database into prompts.

============================================================
8. LINEBANK CHANGE
============================================================

OLD:
LineBank was checked first for every text response.

NEW:
LLM is primary.

Flow:

Start Dialogue LLM
    ↓
If response is fast:
    use LLM response
    store successful response in LineBank

If LLM is slow:
    try LineBank fallback
    if good cached line exists, send it

If LLM errors:
    use LineBank fallback if available

Default soft fallback timeout in rebuild:
3500 ms

Purpose of LineBank:
- timeout fallback
- error fallback
- growing dialogue cache
- speed improvement over time

LineBank is NOT the NPC's primary brain.

============================================================

Sarah → John trust 15

Global trait.trust cannot replace per-target relationships.
